1. What we were asking for

Our team wanted a Splunk endpoint so Power BI could connect and build dashboards showing Smartsheet activity — specifically, who is viewing vs. editing sheets, at a per-workspace / per-project / per-sheet level, over a rolling 90-day window. This was requested by CMC PMs to track update/view activity on RTM-related Smartsheets across ~140 projects.

Note: this is not a data export from Splunk — Power BI would only be reading/visualizing data already indexed in Splunk, not extracting it elsewhere.

2. Splunk team's response

Direct answer: No. The Splunk team will not provide an outbound endpoint/connection that lets external tools (Power BI) pull data out of Splunk.

Why

  • This specific Splunk environment onboards data from 400+ different source systems, some of which contain sensitive data — access is intentionally locked down.
  • Splunk's role here is data onboarding only: they ingest data in, they do not support pulling data back out to external platforms.
  • This is a security/InfoSec policy decision, not a resourcing or technical-capability issue on their side.
  • A similar request was recently made by the Databricks team (wanting a Splunk-to-Databricks connection for monitoring) — that was also declined for the same reason.
  • This environment is specifically used by GCDO (Global Cyber Defense) for security/audit purposes, which is part of why it's tightly restricted.

What Splunk can do instead

  • Apply transforms to data already in Splunk (e.g., rename fields) — but cannot add, remove, or reshape fields.
  • Support building dashboards natively within Splunk on top of indexed data (their own dashboarding tools), rather than exporting to Power BI.
  • Suggested that a separate Splunk environment — ACS (with Splunk Observability) — may be better suited for this kind of monitoring/dashboarding use case, though this wasn't confirmed.

3. Root cause behind the original ask

The underlying need — Smartsheet activity timestamps (who's viewing/editing) — exists because the Smartsheet API is not currently usable directly as a data source for this. That's why the data path was originally set up as Smartsheet → Splunk, and the team then wanted Splunk → Power BI to visualize it. The Splunk team's position blocks that second leg.

5. Bottom line

Power BI cannot be directly connected to this Splunk environment — this is a firm security/InfoSec position, not a technical or resourcing gap, and a comparable request from another team (Databricks) was declined on the same grounds. To get the 90-day view/edit activity data CMC PMs need, the realistic paths forward are: (1) build the dashboard natively in Splunk, (2) investigate whether the Smartsheet vendor can expose the required activity data via their own API, or (3) evaluate the separate ACS/Observability Splunk environment for a possible alternative.
